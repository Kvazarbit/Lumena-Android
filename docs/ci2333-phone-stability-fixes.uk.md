База: `feature/experience-loop-fixes-v1` @ `88820a8a`.
Робоча гілка: `feature/ci2333-phone-stability-fixes-v1`. Android: 0.12.35 / vCode70, Bridge: 0.35.

## Відтворені телефонні збої

- `BRIDGE_START_FAILED` при працюючому Bridge 0.34 через одиночну 900-мс перевірку.
- `project_id` без `projectRoot` дозволяв читати спільний workspace замість каталогу проєкту.
- `PROJECT_CONTEXT_PRIVATE` спричиняв повтори моделі, хоча дозвіл може дати тільки власник.
- `WRITE_WORKSPACE` / заперечення спотворювали критерій `code-action-evidence`.
- `image.search` переривався на TimeoutError першого провайдера.
- `repair_lab_gguf` виглядав як JSON-дослід для архіватора, ламав приватний ZIP-експорт.
- Регресія #27 пропустила semantic mutants через неправильну умову workflow.

## Зроблено

1. Три обмежені read-only probes Bridge замість одного; жодні `file.write` / `python.tests` не повторюються цим механізмом. Дозвіл RUN_COMMAND як і раніше потрібний лише для фактичного автостарту.
2. При логічному ID без фізичного активованого кореня відкривається панель проєктів; додатковий fail-closed контролера блокує всі локальні файлові інструменти.
3. Відмова приватного маршруту тепер завершує спробу з PARTIAL, без повторного звернення до тієї самої хмарної моделі. Правила egress не змінено.
4. GoalContract використовує межі слів для директив, пропускає назви можливостей та заперечені дії.
5. Timeout під час встановлення зв'язку або читання Wikimedia / Openverse є локальною помилкою провайдера; другий провайдер пробується. Не розширено домени безпечних мініатюр.
6. GGUF-кеш зберігається в окремому ключі SharedPreferences; старий ключ не потрапляє в експорт і видаляється після нового хешування. Для локального файлу ключ враховує mtime.
7. На цій гілці регресія запускає два цільові мутанти; результат потрібен з реального CI-лога / artifact. Додані Kotlin, Robolectric та Python регресійні тести.

## Залишкові обмеження

- Вбудована GGUF може бути завантажена до зміни файлу. Хеш вибраного файлу (навіть з mtime) **не є доказом фактично завантажених ваг**. До runtime-attestation лабораторія 50/50 не повинна трактувати цей fingerprint як причинний доказ.
- Більш широкі семантичні помилки GoalContract не виключені новими лексичними тестами. Обов'язкова перевірка негативних прикладів на телефоні.
- `project_id` не означає, що папка автоматично створюється в Termux: потрібен реальний каталог і явний вибір проєкту через UI.
- Передавання історії/коду в хмару, включно з моделями Ollama `:cloud`, дозволяється виключно власником у межах відповідних проєктів.
- Попереднє джерело зображень може бути недоступним, а деякі Openverse-прев'ю відфільтровані обмеженням HTTPS-доменів.

## Приймання

Перевірити Android CI, JUnit, Python unittest та дійсне `KILLED_EXPECTED` для обох мутантів. Після власноручного підпису original key та оновлення Bridge 0.35 перевірити на телефоні:
- реальний `project.inspect` у вибраному каталозі, без переходу до кореня;
- `FAIL → file.patch → PASS` з незмінною owner verification boundary;
- `PROJECT_CONTEXT_PRIVATE` з рівно однією відмовою та без витоку даних;
- timeout першого image-provider з успіхом другого (мок-тест у CI);
- створення приватної ZIP-копії, включно зі старим `repair_lab_gguf`.

Код/CI сам по собі **не є телефонною перевіркою**. Без підтвердження реального процесу не оголошувати P0 закритим.
