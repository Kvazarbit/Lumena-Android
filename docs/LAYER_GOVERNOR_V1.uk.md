# Layer Governor v1: які шари екзоскелета залишити

Статус: **реалізовано в коді, CI зелений (#1963, #1964); на телефоні не перевірено.**
Гілка: `feature/exoskeleton-integrity-v1`. Відповідає Phase 4 roadmap і онлайн-частині S09.
Офлайн-частина S09 (фіксований набір задач, парні прогони A/B) **не виконана**.

## Навіщо

Підрахунок «скільки разів порада стояла поруч з успіхом» не доводить, що порада допомогла.
Легкі задачі вдаються з порадою і без неї. Тому кожен дорадчий шар перевіряється так само,
як ліки: частина задач іде без нього, і результати порівнюються.

## Що керується, а що ні

Керуються (можуть бути приховані в експерименті):
`landscape`, `memory`, `coordinator`, `fractal`, `evidence`, `constitution` (лише LEARNED-рядки), `reflex`.

Ніколи не керуються і не вимикаються: Core DNA, HARD-інваріанти, ToolRegistry/ToolGate,
обмеження користувача, Goal Contract, перевірки ContextKernel, підтвердження дій.

## Як працює

1. Для кожної задачі кожен шар, якому є що порадити, незалежно отримує руку
   `EXPOSED` або `WITHHELD` (20%). Рука = стабільний хеш `task id + layer`, відома ймовірність,
   модель на неї не впливає. Різні шари призначаються незалежно → факторний план.
2. Задача дає вектор конфігурації `x` і результат `f(x)` = кінцевий статус після Goal Contract
   (`DONE` = успіх). Незавершені задачі (скасовані, замінені, старші 6 год, витіснені) →
   `UNRESOLVED`: не входять у частку успіхів, але рахуються по руках.
3. Головний ефект шару = стратифікована за типом задачі різниця скоригованих часток
   (Agresti–Caffo); це еквівалент коефіцієнта Уолша першого порядку для нерівних рук.
   Пари шарів = коефіцієнт Уолша другого порядку, `CONFLICT`, якщо пара шкодить.
4. Вердикти лише в контрольних точках (кожні 100 задач), інтервали з поправкою Бонферроні
   (z=2,69 для 7 шарів, z=3,04 для 21 пари):
   - `KEEP` — нижня межа > 0;
   - `DISABLE` — верхня межа < 0, ≥ 50 задач у кожній руці, **дві контрольні точки поспіль**;
   - `NEGLIGIBLE` — весь інтервал у ±5 п.п.;
   - `NOT_TRIGGERED` — порада була менш ніж у 5% задач;
   - `INSUFFICIENT_DATA` — інакше, а також при `ATTRITION_IMBALANCE` (руки втрачають задачі
     з різницею > 10 п.п.).
5. Автоматично лише вимикає шкідливий шар, окремо для кожної моделі. Задачі з примусово
   вимкненим шаром не входять в оцінку. Повторне ввімкнення — тільки `reset` (новий експеримент).
6. Збій сховища → шари показуються як до появи Governor-а (fail-open), Diagnostics показує помилку.

## Як читати Diagnostics

Секція `[LAYER_GOVERNOR]`:

```
model=ollama:gemma trials=412 checkpoint=400 pending=2 ci=bonferroni-7 disable=two-consecutive-checkpoints
disabled=none
layer=fractal verdict=INSUFFICIENT_DATA delta=+4.1% ci95=[-6.0%,+14.2%] exposed=181/290 withheld=38/71 eligible_share=+90.2% unresolved=9/3
interaction=constitutionxfractal estimate=-12.0% ci95=[-40.1%,+16.1%] tasks=212
```

## Чесні межі

- Повільно: щоб побачити ефект ~10 п.п., потрібно ~700–1100 задач на шар.
  Довго найчастіший вердикт — `INSUFFICIENT_DATA`, і це правильно.
- `DONE` для розмовних задач без критеріїв Goal Contract — слабка мітка. Хибне «готово»
  поки не вимірюється.
- Придатність шару визначається на кожному ході, тож прихований раніше шар може змінити,
  чи матиме пораду інший шар пізніше (невелике зміщення).
- Ефект прив'язаний до моделі; зміна моделі = новий експеримент.

## Тести

`LayerGovernorPolicyTest` (імітація з відомою істиною): корисний шар → KEEP, шкідливий →
DISABLE і примусово вимкнений без зсуву оцінки, нульовий → ні KEEP ні DISABLE, три шари
одночасно, конфліктна пара, парадокс Сімпсона, рідкісний шар, незалежність рук,
стабільність між контрольними точками, 20 нульових експериментів із повторними перевірками,
облік незавершених задач, блокування при різному відтоку.
`AdvisoryHoldoutTelemetryTest`: стабільність руки, частка, історія epoch.
