# Lumena на телефоні: старт за 15 хвилин

Для власника і тестувальників збірки `0.12.21+` (гілка `feature/exoskeleton-integrity-v1`).

## 1. Отримати встановлюваний APK

Android ставить оновлення лише з тим самим підписом. Публічний відбиток ключа власника
закріплено в `signing/certificate.sha256`. Приватний ключ у git не зберігається.

**Варіант A (рекомендовано, один раз).** GitHub → Settings → Secrets and variables → Actions →
New repository secret `LUMENA_SIGNING_BUNDLE` = повний JSON резервного пакета ключа власника.
Після цього кожен зелений CI сам дає артефакт `Lumena-v0.12.21-ci<номер>-arm64` з підписаним APK,
`SHA256SUMS.txt` і `CERTIFICATE-SHA256.txt`.

**Варіант B (вручну, потрібна Java 17).** Завантажити артефакт `UNSIGNED-Lumena-ci<номер>-signing-input`
(у ньому APK і `apksigner.jar`) і виконати в корені репозиторію:

```bash
python scripts/sign_apk.py --apk app-release-unsigned.apk --out Lumena.apk --apksigner apksigner.jar --bundle-file lumena-signing-bundle.json
```

Скрипт відмовиться підписувати чужим ключем і перевірить сертифікат після підпису.

## 2. Встановити поверх наявної версії

1. На телефоні: «Інструменти → Папка пам'яті Lumena → Зберегти зараз» (резервна копія стану).
2. Відкрити APK і підтвердити оновлення. Видаляти стару версію **не потрібно** і не варто:
   видалення стирає приватні дані застосунку.

## 3. Підключити Termux Bridge

У Termux:

```bash
bash termux/install_bridge.sh
python ~/.lumena/bridge.py
```

У Lumena: Налаштування → Bridge → адреса `http://127.0.0.1:8765` і токен з Termux.
Модель: Ollama на телефоні або вбудований GGUF (Налаштування → Модель).

## 4. Перевірити, що працює

Сценарій-приймання (інцидент «реалізуй»):

1. Попросити змінити файл у проєкті, наприклад «у проєкті demo створи hello.py, який друкує привіт».
2. Написати «реалізуй». Очікування: або реальні кроки інструментів, або чесне питання.
   **Ніколи** — миттєве «Task complete.» без жодного кроку.
3. Написати «?». Очікування: пояснення стану попередньої задачі, без веб-пошуку.

## 5. Що дивитися в Diagnostics

Налаштування → Diagnostics → Копіювати. Секції:

| Секція | Що означає |
|---|---|
| `[FRACTAL_TASK_TRAIL]` | оцінений слід кожної задачі: модель, тип, успіх, токени. Спостереження, не причина |
| `[LAYER_GOVERNOR]` | які шари досвіду справді допомагають (`KEEP`), шкодять (`DISABLE`) чи лише коштують токенів (`COSTLY_NO_BENEFIT`) |
| `[COGNITIVE_INFLUENCE]` | як часто шари взагалі спрацьовують і показуються моделі |
| `[CONSTITUTION_GENOME]` | навчені й тіньові правила |

Перші вердикти Governor-а з'являються не раніше ніж після кількох сотень задач.
До того `INSUFFICIENT_DATA` — це нормальний і чесний стан.

## Межі цієї збірки

- Перевірено юніт-тестами в CI, а не на кожному телефоні. Про проблеми — Diagnostics власнику.
- 20% задач свідомо виконуються без частини дорадчих шарів: так система вимірює їхню користь.
  Жорсткі правила безпеки ніколи не вимикаються.
