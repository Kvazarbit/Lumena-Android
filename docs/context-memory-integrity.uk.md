# Цілісність пам’яті ОС контексту

Реалізація на `codex/context-memory-integrity`, поверх LiteRT-LM SHADOW.
`versionCode=60`. Прийняття на телефоні та виграш якості потребують окремих вимірів.

## Першоджерела і робочий контекст

Canvas лишається обмеженою робочою проєкцією на 512 записів. Новий
`lumena_fractal_evidence_ledger_v1.json` зберігає версії першоджерельних записів
окремо. Завантаження старого Canvas ідемпотентно копіює його наявні записи до
журналу. Нові coordinator-приклади архівуються до обрізання Canvas.
Окремі результати інструментів архівуються без очікування повторної спроби або
успішної послідовності. Тому одинична невдача також залишається доступною.

Джурнал не відновлює докази, видалені попередніми версіями застосунку.
Ідентифікатори, task hashes, outcomes та evidence IDs зберігаються. Уточнення
метаданих додає нову ревізію, попередні байти лишаються в журналі; переписування
спостережуваного outcome під тим самим source ID відхиляється.
Поєднані та одиничні записи однієї задачі не збільшують кількість голосів
тієї самої форми принципу.

Невідомий outcome або відсутній receipt зберігається як окремий unresolved
інцидент. Він не перетворюється на Boolean failure або success і не бере участі
в позитивному навчанні. Журнал не дозволяє повторне виконання невідомої операції.

Журнал записується через AtomicFile під StateVaultLock. Він входить до allowlist
StateVault; під час імпорту перевіряються структура, версія та hash кожної ревізії.
Старі копії без журналу читаються; міграція починається з наявного Canvas.
Межа початкового формату — 10 000 ревізій/інцидентів або 32 MiB: переповнення
повертає помилку, без очищення старих негативів. Це атомарний JSON-журнал,
а не необмежена БД; швидкість на великих архівах ще слід виміряти на телефоні.
Він містить ті самі приватні source-поля, що coordinator/Canvas, і потребує
приватної папки резервування. Raw stdout і тексти запитів моделі не додаються.

## Структуровані умови, а не вигадана причина

Нові записи несуть:

- deterministic problem-class hint з TaskIntentRouter;
- типи обов’язкових перевірок GoalContract, без приватних subjects;
- hash Android fingerprint та версії APK;
- hash точних аргументів інструмента для кожного кроку;
- наявні failure classes, залежності, outcomes і посилання на докази.

Problem-class є підказкою класифікатора, а не незалежно перевіреним змістом мети.
Наявність очікуваної перевірки не означає, що вона пройдена. Немає автоматичного
висновку про user-goal success: `independentGoalProofs` залишається нулем.
Для старих записів відсутні умови та причинне пояснення — UNKNOWN.

Embedding отримує клас задачі, типи ресурсів з allowlist, послідовність операцій,
failure classes, очікувані перевірки й тип спостереження. Імена файлів, URL,
raw model prose й приватні залежності не потрапляють у новий embedding-текст.
Це багатший пошуковий опис, але не автоматично знайдений причинний закон.

Контрприклад порівнюється на рівні конкретного tool/target/argument fingerprint
та зафіксованих умов, навіть коли навколишні послідовності інші. Зміна залежності
або середовища не вважається суперечністю за однакових умов. Відсутня інформація
не заповнюється припущенням; legacy-принципи потребують повторної перевірки.

## Семантичний кеш і scope

`null` та історичний `hash("global")` мають однакову семантику GLOBAL у проєкції;
оригінальні receipts не переписуються. Проєктний запит бачить GLOBAL і той самий
проєкт. Глобальний запит не бачить чужі проєкти. Панель читає області з джерел
після відкриття, без обов’язкового повторного індексування; вибір переживає
відтворення UI.

Один ручний запуск індексує наступні 48 відсутніх/застарілих документів. Уже
актуальні ревізії пропускаються. Області й пошук використовують архівні джерела,
а не лише першу сторінку Canvas/Genome. Негативи мають пріоритет, але повторні
запуски просуваються до recovery і позитивних кандидатів. Кеш обмежений 4096
векторами та 16 MiB векторних даних; переповнення явне й не видаляє source journal.

Ревізія документа охоплює dependencies, argument/target applicability,
структуровані умови, provenance, контрприклади й облікові показники, навіть якщо
embedding-текст обрізано до 700 символів. Застарілий вектор не повертається як
актуальна підказка. Зміна формату V0 → context-V1 вимагає переіндексування.

## Перевірки та подальше приймання

`ContextMemoryIntegrityTest` перевіряє GLOBAL, просування сторінок, інвалідацію,
контрприклади між різними послідовностями, зміну умов, приватність embedding-тексту,
негатив за межами Canvas, ідемпотентність/версії журналу, tamper/capacity refusal,
StateVault round-trip, одиничну невдачу й UNKNOWN без навчального голосу.
CI вимагає фактичного виконання цього suite без skips/errors/failures.

Перед прийманням на телефоні: резервна копія, owner-signed APK, порівняння source IDs
до/після міграції, повторне відкриття scope selector, STOP між пакетами,
перевірка пошуку старого негатива й відновлення StateVault. Для відкату зберегти
попередню копію; архів новішого versionCode не імпортується старішою APK.

Для оцінки користі слід заморозити корпус/ревізії, ваги моделі, runtime,
query/document options та дозволи. На незалежних нових задачах порівняти
memory OFF, lexical-only та hybrid retrieval, зі сліпими мітками й однаковою
перевіркою мети. Вимірювати Recall@5/nDCG, хибний DONE, повтор тупиків,
досягнення мети, втручання власника, latency/tokens/battery. CI й synthetic fixtures
цього виграшу не доводять. Семантичний модуль лишається ручним SHADOW;
ToolGate, Constitution та повноваження не змінюються.
